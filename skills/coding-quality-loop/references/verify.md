# Verify 阶段

## 目标

在一轮代码改动后，用机械性检查确认结果不是“看起来能跑”。

## 触发条件

- 一轮实现完成
- bugfix 完成后
- 用户明确触发 `/verify`

## 最小流程

1. 跑 build 或等效编译检查
2. 跑 types、lint、tests 或最近似替代项
3. 查看 changed files 或 diff
4. 记录失败项、跳过项、风险项
5. 给出 `ready` 或 `not-ready`

## 重点问题

- 构建是否通过
- 类型/静态检查是否通过
- 测试是否通过
- diff 中是否有无关改动、调试残留、遗漏边界

## 不要做

- 只跑一条测试就宣布完成
- 只看命令输出，不看 diff
- 把“项目里没有某项检查”直接算成通过
