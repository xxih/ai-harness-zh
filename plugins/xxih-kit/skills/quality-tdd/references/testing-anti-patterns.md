# Testing Anti-Patterns

## 1. 测 mock，不测行为

- 反例：只断言 mock 被调用次数，却没有验证真实外部行为
- 风险：测试通过，但真实逻辑仍可能错误
- 改法：优先验证输入输出、状态变化、边界结果

## 2. 一个测试塞多个行为

- 反例：一个测试同时覆盖“重试 + 日志 + 回退 + 指标”
- 风险：失败时不知道到底哪一层坏了
- 改法：一条行为一个测试，名字里不要出现多个 `and`

## 3. 先写实现再补测试

- 反例：代码先跑通，再补一个“证明它能跑”的测试
- 风险：测试只是在为当前实现背书，不能证明需求被锁定
- 改法：先让测试失败，再写实现

## 4. 为了好测而加 test-only 接口

- 反例：专门暴露生产代码中的内部状态给测试读
- 风险：污染设计边界
- 改法：优先从公开行为验证，必要时重构真实接口

## 5. 只测 happy path

- 反例：只测成功分支，不测错误、边界、重试、空值
- 风险：线上最常爆的恰恰是这些场景
- 改法：至少覆盖异常路径、边界值和回归样例
