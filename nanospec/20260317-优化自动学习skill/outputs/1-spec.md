# 规格说明：优化自动学习 skill

## 1. 背景

当前仓库已有 `learning-capture` skill，用于手工触发学习积累，并把产物分成三类：

- `learnings.md`
- `promote-candidates.md`
- `project-rules.md`

用户对现有结果的反馈是：这三类里只有 `project-rules.md` 稍微有用，另外两类容易变成“有记录但没推动力”的碎片。尤其在“把一篇文章改写成小红书风格并导出图文”这种真实任务里，真正值得沉淀的东西更像一个可复用 workflow / skill，而不是若干零散小点。

## 2. 本次要回答的问题

1. 这三个文件各自的准确定位是什么。
2. 为什么当前产出会让人觉得只有 `project-rules.md` 有价值。
3. `learning-capture` 应如何调整，才能更稳定地把有价值的经验导向 skill / command / eval，而不是停在记录层。

## 3. 三类文件的定位

### 3.1 `learnings.md`

定位：任务内或相邻任务可直接复用的“操作性经验”记录。

它应回答的是：

- 下次遇到类似问题，第一反应该检查什么
- 哪个信号说明问题可能出在某个环节
- 已验证过的动作是什么

它不应承担：

- 定义共享 skill 的完整骨架
- 承担仓库级规则沉淀
- 重复改写 `promote-candidates.md` 的内容

### 3.2 `promote-candidates.md`

定位：从“有价值经验”到“正式共享资产”的中间孵化层。

它应回答的是：

- 这次经验最适合升级成什么资产：`skill`、`command`、`eval`、`README` 说明，还是吸收到现有资产
- 资产的触发场景、输入、输出、边界、依赖是什么
- 为什么它值得跨任务复用，而不是只留在当前任务

它不应只是：

- 把 `learnings.md` 换个标题重写一遍
- 泛泛地说“这个以后可能有用”

### 3.3 `project-rules.md`

定位：项目级 / 仓库级规则修正的候选池。

它应回答的是：

- 用户这次纠正的到底是哪条长期规则
- 这条规则应该更新到哪里
- 当前只做排队，还是已经足够明确到可以后续写回 `AGENTS.md`、README 或某个 skill

它天然更容易有价值，因为：

- 用户纠正通常更明确
- 作用范围更稳定
- 后续落点更清楚

## 4. 当前问题定义

### 4.1 三类文件被设计成“都要产出”，导致信噪比下降

一旦默认每次都要写满三类，agent 很容易为了满足结构而补齐低质量条目。结果是：

- `learnings.md` 里混入“其实应该升级成 workflow”的内容
- `promote-candidates.md` 里只有一句模糊候选名
- 真正有效的只有带明确纠正的 `project-rules.md`

### 4.2 `promote-candidates.md` 缺少“资产化骨架”

当前模板只要求“想沉淀的模式”“为什么可能跨任务复用”，这足够做想法记录，但不足以支撑后续真正产出 skill。它缺少至少以下信息：

- 建议资产类型
- 典型触发语
- 输入材料
- 关键步骤
- 期望输出
- 不适用边界
- 需要的验证 / eval

### 4.3 缺少“流程型经验优先升级”的判断规则

像“小红书改写并导出图文”这种任务，价值不在单点经验，而在一整条工作流：

- 原文改写
- 风格调整
- 渲染链路选择
- 产物目录落位
- 导出与验收

这类场景如果只拆成普通 learning，会天然失焦。

## 5. 优化目标

### 5.1 改成“主产物优先，其他产物按证据补充”

不是每次都追求三份文件都很重，而是先判断本次主价值落在哪一层：

- 偏操作经验：主写 `learnings.md`
- 偏共享资产候选：主写 `promote-candidates.md`
- 偏规则纠正：主写 `project-rules.md`

其他文件只有在确有证据时再补。

### 5.2 强化 `promote-candidates.md` 的 workflow / asset 视角

当经验明显是一条可复用流程时，`promote-candidates.md` 应直接逼近“skill 草案”，至少包含：

- 资产类型
- 触发场景
- 输入
- 输出
- 步骤骨架
- 依赖与边界
- 建议 absorb 位置
- 需要补的 eval

### 5.3 让 `learning-capture` 成为“通往资产化的入口”

这个 skill 不该只负责归档，还应该帮助判断下一步：

- 保持任务内记录
- 升级为某个现有 skill 的补充
- 新建一个 workflow skill
- 仅提炼为项目规则

## 6. 本次任务的完成标志

满足以下条件即可认为本轮澄清完成：

1. 三类文件的职责、边界与主次关系被明确写清。
2. 当前“只有 `project-rules.md` 稍有价值”的原因被明确指出。
3. 给出一版可执行的优化方向，尤其覆盖“流程型经验优先进入 `promote-candidates.md`”。
