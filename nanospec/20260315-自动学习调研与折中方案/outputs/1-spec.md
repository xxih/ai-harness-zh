# 规格说明：自动学习调研与折中方案

## 1. 背景

当前仓库正在沉淀可复用 prompt 资产。用户希望沿“自动学习 / 自动积累”方向先开一个研究任务，但明确不要求一开始就做到全自动。

已知约束：

- ECC 当前在这条线上的实现更强，但较强依赖 hooks。
- prompt 优化和经验判断本质上仍需要人类参与。
- AI 的目标不是完全替代人，而是降低经验沉淀成本、提高复盘与归档效率。

## 2. 任务目标

本次任务分两层：

1. 先完成研究结论，明确自动学习能力地图与折中方案。
2. 基于用户最新决策，先落第一阶段的“纯手工触发”能力。

当前阶段需要回答并落地的核心问题：

1. 三个参考 repo 是否已经具备“自动学习 / 积累”相关能力。
2. 这些能力分别依赖哪些载体：skill、command、memory、hooks、observer、运行时插件等。
3. “ECC 强依赖 hooks”这件事对当前仓库意味着什么。
4. 若先做纯手工触发，当前仓库应先确定什么规范、目录结构与产出物结构。
5. 第一阶段最小 skill 应如何定义，才能在一个会话或一个任务内手动触发学习积累。

## 3. 调研范围

本次仅覆盖以下三个参考仓库：

- `references/repos/everything-claude-code`
- `references/repos/superpowers`
- `references/repos/oh-my-opencode`

调研对象包括：

- README、技能说明、命令说明
- hooks / reminder / memory / learning 相关实现
- 与“学习记录”“经验回流”“长期资产化”直接相关的文件

## 4. 需要产出的结果

### 4.1 研究结论

需要形成一份证据化研究文档，至少包含：

- 三仓库是否具备对应能力
- 每个仓库的能力载体与依赖方式
- 对当前仓库的可吸收点与不宜直接吸收点

### 4.2 方案设计

需要给出多种折中方案，而不是单一结论。

方案设计至少应覆盖：

- 完全手动但 AI 辅助
- 半自动候选生成 + 人工确认
- 任务内自动传播 learnings，但长期入库保持人工确认
- 仅在适配层使用提醒型 hooks 的增强路径

### 4.3 第一阶段资产落地

需要新增一个最小可用 skill，满足以下要求：

- 手动触发，而不是自动观察
- 优先服务单个会话或单个任务
- 先定义学习记录结构，再考虑后续自动化
- 支持任务容器优先、项目本地回退的双层落盘策略
- 不直接把学习记录升级为正式共享资产
- 除普通 learnings 外，还要支持“项目级 / 公共规则候选”的捕获
- 对话中用户纠正出来的仓库级规则，应能先排队到候选文件，而不是要求立即手改 `AGENTS.md`
- learning 默认落盘到项目根目录 `.learning/`，不以 `nanospec` 为默认学习载体
- quality 类 skill 若存在任务容器，则优先回写容器；否则回退到 `.quality/`
- research / orchestration 类记录默认回退到 `.research/`

### 4.4 推荐路径

需要给出一条面向当前仓库阶段的推荐路线，明确：

- 第一阶段先做什么
- 哪些能力应延后
- 为什么不建议直接复制 ECC 的全自动 hooks 方案

## 5. 非目标

本次不做以下事情：

- 不在当前仓库直接实现 hooks 驱动的自动学习系统
- 不设计完整的 observer / memory / instinct runtime
- 不把本次产出做成对任何单一平台强绑定的机制
- 不在第一阶段实现半自动候选扫描或自动积累

## 6. 验收口径

当以下条件满足时，可认为本次任务完成：

1. `assets/auto-learning-landscape.md` 存在，并给出三仓库的具体证据与判断。
2. `src/skills/learning-capture/SKILL.md` 存在，并清楚定义手工触发、目录结构与产出物结构。
3. `outputs/2-plan.md` 中明确给出折中方案、第一阶段范围与推荐路径。
4. 结论清楚回答“为什么不一定要全自动”和“人类应保留在哪个环节”。
