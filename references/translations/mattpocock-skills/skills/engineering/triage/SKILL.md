# Triage

> 原文:[skills/engineering/triage/SKILL.md](https://github.com/mattpocock/skills/blob/main/skills/engineering/triage/SKILL.md)

把项目 issue tracker 上的 issue,在一个小的"triage 角色"状态机里推进。

triage 期间在 issue tracker 上贴的每一个 comment 或 issue,**必须**以这段免责声明开头:

```
> *This was generated by AI during triage.*
```

## 参考文档

- [AGENT-BRIEF.md](AGENT-BRIEF.md) — 怎么写"经得起放久"的 agent brief
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md) — `.out-of-scope/` 知识库怎么运作

## 角色

两个**类别(category)**角色:

- `bug` — 坏了
- `enhancement` — 新功能或改进

五个**状态(state)**角色:

- `needs-triage` — 维护者需要评估
- `needs-info` — 等报告人补信息
- `ready-for-agent` — 已完整规格化,可以交给 AFK agent
- `ready-for-human` — 需要人来实现
- `wontfix` — 不修

**每个被 triage 过的 issue 都应该恰好挂一个 category 角色 + 一个 state 角色**。state 角色冲突时,先标记并问维护者,再做其它事。

这些是**规范角色名**——issue tracker 里实际用的标签字符串可能不一样。映射应该已经提供给你了——没有的话跑 `/setup-matt-pocock-skills`。

**状态迁移**:无标签 issue 通常先到 `needs-triage`;从那里转到 `needs-info`、`ready-for-agent`、`ready-for-human` 或 `wontfix`。`needs-info` 在报告人回复后回到 `needs-triage`。**维护者可以随时手动覆盖**——看到不寻常的迁移先标记问一下再做。

## 调用方式

维护者输入 `/triage` 并用自然语言描述想要什么。**解读请求并行动**。例子:

- "把需要我看的列出来"
- "看看 #42"
- "把 #42 移到 ready-for-agent"
- "agent 现在能拿哪些?"

## 列出需要关注的

查 issue tracker,展示三个桶,**最老在前**:

1. **未打标签** —— 从没被 triage 过
2. **`needs-triage`** —— 评估中
3. **`needs-info` 且报告人在上次 triage 笔记后有新活动** —— 需要重新评估

显示数量 + 每个 issue 一行简介。让维护者挑。

## 对某个具体 issue 做 triage

1. **采集上下文**。读完整个 issue(正文、评论、标签、报告人、日期)。解析之前的 triage 笔记,**别再问已经解决过的问题**。用项目领域术语表探索代码库,尊重相关区域的 ADR。读 `.out-of-scope/*.md`,把和当前 issue 像的"之前的拒绝"翻出来。

2. **给建议**。告诉维护者你推荐的 category + state + 理由,加一段与 issue 相关的代码库摘要。等指示。

3. **复现(只对 bug)**。在任何 grilling 之前,先**尝试复现**:读报告人的步骤、追相关代码、跑测试或命令。报告发生了什么——成功复现 + 代码路径、复现失败、信息不足(强 `needs-info` 信号)。**确认能复现会让 agent brief 强很多**。

4. **Grill(如有需要)**。issue 需要细化的话,跑一次 `/grill-with-docs`。

5. **应用结论**:
   - `ready-for-agent` —— 发一条 agent brief 评论([AGENT-BRIEF.md](AGENT-BRIEF.md))
   - `ready-for-human` —— 结构同 agent brief,但说明为啥不能下放(判断、外部访问、设计决策、手动测试)
   - `needs-info` —— 发一条 triage 笔记(模板见下)
   - `wontfix`(bug)—— 礼貌解释,然后关
   - `wontfix`(enhancement)—— 写到 `.out-of-scope/`,在评论里链过去,然后关([OUT-OF-SCOPE.md](OUT-OF-SCOPE.md))
   - `needs-triage` —— 打上角色。如果有部分进展,可选写评论。

## 快速 state 覆盖

如果维护者说"把 #42 移到 ready-for-agent",**信他,直接打角色**。**先确认你接下来要做什么**(改角色、写评论、关闭),然后动手。跳过 grilling。如果是迁到 `ready-for-agent` 但没做 grill,问下要不要写 agent brief。

## Needs-info 模板

```markdown
## Triage Notes

**What we've established so far:**

- point 1
- point 2

**What we still need from you (@reporter):**

- question 1
- question 2
```

把 grilling 中解决掉的所有事写进 "established so far",**别让那些工作丢了**。问题必须具体可执行,不能是"请提供更多信息"这种废话。

## 续接上次会话

如果 issue 上有之前的 triage 笔记,**读它**,看报告人有没有回答未决问题,**呈现更新后的图景再继续**。别再问已经解决过的问题。
