# Learning Capture

把“这次值得记住什么”做成显式手动动作。当前阶段只做手工触发，不依赖 hooks、observer 或自动入库。目标是在单个会话或任务内先沉淀两类东西：规则候选，以及其他可复用记录。默认落盘位置放在 `.learned/`。

## 何时使用

- 你刚完成一个非平凡任务，想把这次经验记下来
- 你明确说了“复盘一下”“沉淀一下这次经验”“手动触发学习积累”
- 同一任务里出现了用户纠正、关键取舍、验证教训或可复用 workaround
- 你还不确定是否值得升级为正式 skill / command 或其他长期资产，但不想让经验只留在对话里
- 用户在对话里纠正了几个项目级 / 公共规则点，但你不想立刻手改正式文档

不适用：

- 只是一次性 typo、机械改名或纯偶发问题
- 还没有形成任何可复用结论或证据
- 目标是直接产出正式 skill / command 或长期规范，而不是先做记录

## 产物

每次使用本 skill，默认优先产出以下两类记录：

1. 其他记录
   - 若当前任务已有自己的记录文件，优先回写到该文件
   - 若没有既定记录位置，默认写入 `.learned/notes.md`
   - 记录单点经验、流程草案、候选资产、局部验证结论
2. 规则候选
   - 若当前任务已有自己的记录文件，优先回写到该文件
   - 若没有既定记录位置，默认写入 `.learned/rules.md`
   - 只记录项目级 / 团队级 / 分发级的长期规则修正

默认要求：

- 先判断本次主价值属于 `rules` 还是 `other`，不要两边平均用力
- 一条记录只描述一个明确模式，不要把多个问题揉成一条
- 每条都要写证据来源，而不是只写抽象结论
- 当前阶段只做记录和分类，不自动升级为正式共享资产

## 工作流

1. 确认本次学习边界
   - 本次目标是“任务内 / 会话内积累”，不是立即发布正式资产
   - 只抓非平凡、可复用、带证据的模式
2. 判断记录入口
   - 如果用户纠正的是长期口径、目录约定、公共规则，优先写 `rules.md`
   - 其他内容统一先写 `notes.md`
   - 如果一条经验明显已经接近完整 workflow，也先写进 `notes.md`，但按“候选资产草案”来写
3. 收集证据
   - 优先看本次 diff、命令输出、验证结果、用户纠正、失败与修复过程
   - 如果没有证据，只能记录为疑似观察，不能写成确定模式
4. 提炼记录
   - `notes.md` 只保留最少字段：做了什么、为什么值得记、证据、下一步
   - `rules.md` 只保留最少字段：规则、证据、建议落点、下一步
   - 能落到具体命令、文件、检查动作时，就不要只写口号
5. 如任务口径因此变化，执行对齐
   - 若记录内容影响当前任务范围、方案或后续动作，更新 `alignment.md`
   - 若当前任务已有自己的任务清单，也把后续动作同步回去

## 公共规则捕获

- 如果用户在对话里纠正的是“以后都该这样做”的规则，不要混进 `notes.md`。
- 这类内容应单独写入 `rules.md`，至少包含：
  - 规则
  - 证据
  - 建议落点：项目指令文件、README、某个 skill 或其他长期文档
  - 下一步：`propose-rules-doc-update` | `keep-local` | `drop`
- 当前阶段默认只“提取并排队”，不自动改写正式文档；是否正式写回由后续任务决定。
- 如果用户明确要求“顺手把规则文档也改了”，那是下一步 execute，不属于本 skill 的默认动作。

## 记录约束

- 这个 skill 是手工触发入口，不依赖 hooks 或后台观察器
- 当前阶段不自动生成正式 skill、command 或其他派生资产
- 任务内记录和正式共享资产要分层，不要把原始记录直接当成最终 prompt
- 默认保持独立，不把某个仓库的内部源码目录、任务容器或分发目录写成前提；但学习记录默认可落在 `.learned/`
- 若一条经验只适用于当前项目、当前目录或当前任务，可在 `notes.md` 中标记 `keep-local`
- 若一条经验明显已经具备跨任务复用的完整流程，可在 `notes.md` 中标记 `promote-later`
- 若一条纠正已经明显是公共规则，应优先进入 `rules.md`，不要混进普通 `notes.md`
- 若已有相同记录，优先合并，不要制造新的碎片文件
